# MVP implementation and audit — 2026-07-29

This document preserves historical validation evidence from the initial private implementation. Current release claims are defined by `README.md`, `docs/architecture.md`, and CI.

## Scope

Repository: local DevPlane checkout.

Upstream inspected and exercised: a local GitHub Spec Kit checkout at commit `f36634b5c1463d3592382e863cd5e7b8a94d9c9a`.

Runtime inspected: Hermes Agent `0.19.0`.

## Architecture verified

- GitHub Spec Kit remains the SDD workflow engine.
- DevPlane is a separate wrapper/control-plane repository; no upstream files were modified.
- The native Spec Kit `hermes` integration is used.
- Hermes is selected explicitly with workflow input `integration=hermes`.
- DevPlane adds deterministic manifest/context resolution, drift checks, a managed `.hermes.md` contract, and local JSONL audit records.
- No MCP server is required by the MVP.

## Subagent review

Two batches of three MiniMax review tasks were launched.

Successful architecture worker findings:

- Correctly discovered that the tested Spec Kit version shipped a native Hermes integration.
- Correctly recommended an external wrapper rather than a fork.
- Correctly identified workflows, presets, extensions, bundles, and integration dispatch as the relevant upstream boundaries.
- Correctly warned that Spec Kit's Hermes skills were installed globally under `~/.hermes/skills/` at the time of testing.
- Correctly identified runtime permission enforcement as the main remaining architectural gap.

Rejected worker claim:

- One worker claimed `devplane run` did not execute the real Spec Kit workflow and could only block at a gate. This was disproved by a real non-TTY subprocess smoke test: Spec Kit returned a paused `speckit` run at `review-spec`, and a controlled Hermes executable received the expected skill invocation. The valid part of the finding was the missing wrapper for resume; `devplane resume <run-id>` was added.

Accepted worker findings fixed after review:

- `validate` previously trusted the empty `.hermes/skills` marker. It was changed to parse `.specify/integration.json`, require Hermes to be installed/default, and check the tested Spec Kit compatibility line.
- Audit fields returned by Spec Kit could overwrite DevPlane's authoritative workflow/integration fields. Trusted fields are now applied last and covered by a regression test.
- Paused workflow runs had no DevPlane resume command. `devplane resume <run-id>` was added with audit recording.

Delegation-runtime limitation observed:

- Four delegated review tasks failed before analysis because the then-current MiniMax delegation runtime raised a serialization error after retries. Their transcripts contained no usable findings, so security and quality checks were completed directly with local tools. This is historical evidence, not a claim about current Hermes releases.

## Security audit

Implemented controls:

- YAML uses `yaml.safe_load`.
- Catalog source, capability references, and context resources are resolved and checked against allowed roots.
- Symlink escapes are rejected and covered by a test.
- Subprocesses receive argument arrays and use `shell=False`.
- Failed subprocess messages omit full arguments to avoid exposing feature descriptions.
- Audit logs store a SHA-256 digest of the feature description rather than its plaintext.
- Generated manifests contain relative resource paths and no generation timestamp.
- Manifest and context drift are checked before workflow execution.
- Stale generated context files are removed by `sync` and rejected by checks.
- Existing `.hermes.md` content is preserved; a delimited managed contract is inserted.

Historical tool results:

- Bandit: zero medium/high findings; two expected low findings for importing and invoking `subprocess` with `shell=False`.
- `pip-audit --strict`: no known dependency vulnerabilities.
- Ruff: clean.
- `git diff --check`: clean.

Open risks accepted for the MVP:

1. Resolved write scopes and shell allowances are prompt-level upper bounds, not OS/runtime enforcement.
2. Catalog Markdown is trusted prompt material; there is no signing or prompt-injection scanner.
3. Path validation and file reads are not a transactional snapshot, leaving a local TOCTOU window if a catalog changes concurrently.
4. JSONL audit writes do not use locking, signatures, or tamper evidence.
5. Dependency resolution supports exact capability pins only; no SemVer ranges or dependency graph.
6. External initialization failures may leave partial source files.
7. The tested Spec Kit integration installed Hermes skills in the user-global skills directory; users should verify current upstream behavior.
